# Release 1.0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar 1.0.1 en PyPI con el flag `--version` que ya está en `develop`, los classifiers completos, y el README coherente con un paquete publicado.

**Architecture:** No hay código nuevo. El flag `--version` se commiteó en `05ff943` y está sin publicar. Esta versión es metadata y documentación: los classifiers que PyPI usa para filtrar y ordenar búsquedas, y el estado del proyecto en el README, que todavía dice "en construcción" mientras el paquete ya está en el índice. El release se dispara con un tag y ahora se detiene en el gate de aprobación del environment `pypi`.

**Tech Stack:** Python 3.10+, hatchling, GitHub Actions, PyPI trusted publishing (OIDC).

## Global Constraints

- **Sin `Co-Authored-By: Claude`** ni ninguna atribución al asistente en commits ni en descripciones de PR.
- **Sin emojis** ni iconos decorativos en ningún archivo.
- **Sin em dashes.** Coma, punto o dos puntos.
- El número de versión tiene **una sola fuente**: `portmaster/__init__.py`. `pyproject.toml` lo lee con `dynamic = ["version"]`.
- El tag tiene que ser `v` + el valor exacto de `__version__`, o el job `build` corta antes de publicar.

- CI corre la suite en Ubuntu, macOS y Windows con 3.13, más un job extra de Ubuntu con 3.10.
- Trabajo sobre `develop`. `main` solo se toca por PR.
- El entorno `pypi` exige aprobación de TicoraX antes del job `publish`.

### Task 1: Classifiers y coherencia del README

Los classifiers son los campos con los que PyPI arma su navegación por categorías. Hoy `portmaster` declara cinco y ninguno dice qué versiones de Python soporta ni de qué tipo de herramienta se trata, así que no aparece en ningún filtro. En el mismo movimiento va la línea del README que dice "en construcción", escrita antes de que existiera un paquete publicado.

Sobre declarar 3.10 a 3.13: la CI prueba el piso y el techo de ese rango, y no hay código condicionado por versión de intérprete en el paquete. Declarar los cuatro es honesto. Si en algún momento aparece un `sys.version_info` en el código, este razonamiento deja de valer y hay que agregar los intermedios a la matriz de CI.

**Files:**
- Modify: `pyproject.toml:13-19` (bloque `classifiers`)
- Modify: `README.md:3-14` (badges y línea de estado)

**Interfaces:**
- Consumes: nada de tareas anteriores.
- Produces: `pyproject.toml` con los classifiers que la Task 2 va a empaquetar y la Task 3 va a publicar. Ningún símbolo de código.

- [ ] **Step 1: Escribir el chequeo que falla**

El paquete construido es lo que ve PyPI, no el `pyproject.toml`. El chequeo lee el `METADATA` del wheel, que es el artefacto real.

Crear `scripts/check_metadata.py`:

```python
"""Verifica que el wheel declare los classifiers que PyPI usa para filtrar.

No es un test de pytest a proposito: no corre en CI ni en cada commit, corre
una vez por release contra el artefacto construido. Un test que afirma el
contenido de pyproject.toml solo se afirma a si mismo.
"""

import email
import pathlib
import sys
import zipfile

ESPERADOS = {
    "Development Status :: 5 - Production/Stable",
    "Environment :: Console",
    "Intended Audience :: Developers",
    "License :: OSI Approved :: MIT License",
    "Operating System :: OS Independent",
    "Programming Language :: Python :: 3",
    "Programming Language :: Python :: 3.10",
    "Programming Language :: Python :: 3.11",
    "Programming Language :: Python :: 3.12",
    "Programming Language :: Python :: 3.13",
    "Topic :: Software Development",
    "Topic :: System :: Systems Administration",
    "Topic :: Utilities",
}


def main() -> int:
    wheels = sorted(pathlib.Path("dist").glob("*.whl"))
    if not wheels:
        print("no hay wheel en dist/: corre `python -m build` primero")
        return 1
    wheel = wheels[-1]

    with zipfile.ZipFile(wheel) as z:
        nombre = next(n for n in z.namelist() if n.endswith(".dist-info/METADATA"))
        meta = email.message_from_bytes(z.read(nombre))

    presentes = set(meta.get_all("Classifier") or [])
    faltan = ESPERADOS - presentes
    sobran = presentes - ESPERADOS

    print(f"{wheel.name}: {len(presentes)} classifiers")
    for c in sorted(faltan):
        print(f"  falta: {c}")
    for c in sorted(sobran):
        print(f"  no esperado: {c}")

    version = meta.get("Requires-Python")
    print(f"Requires-Python: {version}")
    if version != ">=3.10":
        print("  Requires-Python no coincide con el piso declarado")
        return 1

    return 1 if faltan else 0


if __name__ == "__main__":
    sys.exit(main())
```
